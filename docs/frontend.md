# Frontend

> 状态：Current（后续 Phase 小节为历史增量记录）

解析工作台只临时展示阶段进度，不展示或长期保存解析 block/chunk 事件；任务结束后应通过
文档详情和切片页面查看最终结果。上传选择器不设置文件大小限制。
> 维护日期：2026-07-15

前端使用 Vue 3、Vue Router 和 Vite，用户可见文案保持中文。

当前质量入口：

```bash
npm run typecheck
npm run lint
npm run test
npm run check
```

图片媒体地址统一通过 `src/utils/media.ts` 解析，页面不应各自维护 `url/image_url/path/base64`
兼容规则。普通 chunk API 只返回向量预览，不返回完整 embedding。

## DCP-1.1 文档布局验收

PDF 的 `DocumentContentView` 在当前 Canonical artifact 存在视觉布局数据时显示“布局验收”
开关。验收模式按页展示归一化 visual/text bbox、稳定 VisualItem 编号、作品数、歧义文本、
未绑定文本、重复 fallback、保守降级原因和关系明细。视觉区域与文本区域可独立开关，点击作品
可查看其 asset、状态和 evidence。

普通 PDF 查看不预取布局账本；首次点击“布局验收”时先读取轻量页面索引，再按当前页请求完整
区域和关系。切换页时仅替换单页数据，避免长文档一次返回全部文本节点。

当前画布是归一化坐标示意图，不等同于 PDF 像素级渲染；原 PDF 页面底图、关系连线和来源图层
筛选留到 DCP-5.1。页面明确展示 `Shadow/Active`，shadow 结果不能被解释为已改变切分或索引。

## DCP-2.1 多轴画像验收

文档详情页在新解析产物存在时展示 DCP-2.1 只读卡片：文档级布局、文本来源、OCR 可信度分布
和语义提示；逐页查看布局、来源、shadow 准入建议、OCR 分数/分档、VisualItem 数量、歧义文本、
不确定原因和 contribution evidence。旧解析产物明确提示尚未生成并需重新解析。前端不执行
OCR 质量判断，也不能把 shadow 建议写回生产。详情页首次只读取轻量页面索引，随后按当前页
加载完整 evidence，避免长文档一次传输并渲染全部页面画像。

DCP-3.1 开启后，同一页面继续展示生产投影结果：顶部汇总 MinerU OCR 的
`normal/auxiliary/shadow` 数量以及 VisualItem/page-overview parent 执行情况；逐块展示来源、准入、质量分、
bbox、reasons 与原始 OCR。原始文本只在用户切到具体页面时懒加载。这里展示的是后端已执行的
生产决策，不在浏览器中重新评分；“已隔离”表示未进入 reflow/Canonical/text child，而不是删除
原始 PDF 或 debug artifact。
